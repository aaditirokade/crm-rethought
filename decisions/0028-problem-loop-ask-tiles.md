# 0028 · The problem as a loop, Ask as tiles

**Date:** 2026-11-06

**Decision:** on the case study home, the problem chapter no longer shows three big percentages. It plays a short loop in three beats, each with its number and source:

1. **A seller's week:** ten blocks rise, and only four are selling (40%).
2. **Typing up the call:** a call log fills itself in while the minutes run (68% say note taking and data entry take the most time).
3. **Trusting the record:** a list of accounts gets flagged stale one by one (76% say less than half their CRM data is accurate).

The loop moves on every few seconds. It can be paused or stepped through with the beat buttons, and it stays still for reduced motion. All three findings are also written out for screen readers. The charts use the soft teal and the warning wash, never violet.

The Ask chapter's four parts (reads, answers, sums up, changes nothing) become four sand tiles in a two by two grid instead of a ruled list.

**Why:** three big numbers state the problem but don't show it. The loop shows what those numbers feel like for the person keeping the record. The tiles give each part of an answer the same weight and are easier to scan than a list.

**Checks:** axe clean in light and dark at 375px and 1440px; no sideways scrolling; the panel keeps one height across beats, so the page doesn't jump.
