# 2026-11-05 · Session 01 · Planning, industry, research approach, naming

**Tool:** Claude (desktop app, with access to my portfolio repo)
**Phase:** 0, setup and planning

Prompts are edited for clarity, with the context, constraints and checks spelled out. What came back and what I decided are as they happened.

---

### Prompt 1 · Planning
**Prompt:**
> I'm starting a new public portfolio project, CRM Rethought: a B2B CRM redesigned from the ground up with AI inside every workflow. My earlier CRM case study is under NDA, so nothing from it can be reused. Plan the project in phases, from setup to case study. Cover:
> - **Every CRM workflow:** where AI helps and where a person must decide.
> - **A UI direction.**
> - **A prompt log:** a format for logging every prompt I write.
> - **How the work is shown:** code on public GitHub, a live prototype, and the prompts and decisions behind it.
>
> Flag anything that puts the NDA at risk.

**Why:** get a full plan before touching code.
**What came back:** a six phase plan (setup, research, define, design, build, test and tell), AI ideas for nine CRM workflows, a UI direction, a prompt log format, and a warning: a public copy of the earlier CRM is not safe.
**My call:** started from zero in a clean room instead of duplicating the earlier project ([decision 0001](../decisions/0001-clean-room.md)).

### Prompt 2 · Industry
**Prompt:**
> Pick the industry this project should serve so it helps me get hired. Weigh three things:
> - where product design jobs are,
> - which employers sponsor and transfer H-1B visas,
> - which industry keeps clear distance from my finance background.
>
> Give a first and a second choice with reasons. List what I should confirm with an immigration lawyer rather than take from you.

**Why:** the project should help me get hired, so its industry should match where design jobs are.
**What came back:** B2B enterprise SaaS, especially software for sales and customer teams, with fintech as a strong second; plus notes on H-1B transfers to confirm with a lawyer.
**My call:** B2B SaaS account teams ([decision 0002](../decisions/0002-industry.md)).

### Prompt 3 · Research approach
**Prompt:**
> I don't have time to recruit real interviewees. Design a research approach that stays honest:
> - build five personas and their interviews from real, linked public sources (reviews, surveys, forums);
> - tie every pain to a source;
> - label everything SIMULATED.
>
> List what real interviews and usability tests should check later.

**Why:** time.
**What came back:** a plan to ground every persona in real public complaints, link each one, label everything SIMULATED, and list real sessions as the next step rather than skip them.
**My call:** simulated, labeled research for this round ([decision 0003](../decisions/0003-simulated-research.md)).

### Prompt 4 · Naming
**Prompt:**
> Suggest names for the product. Each should be two words at most, say what the product is for (preparing for client conversations), and be easy to say in an interview. For each, run a quick web check for existing products with that name and say why it works or doesn't. Don't spend long: if nothing is clearly free, recommend a working title.

**Why:** a name that says what the product is for and is free to use.
**What came back:** Groundwork, Throughline, Dealwork, Footing, Spadework and a few more, with quick web checks; the names that fit best were taken.
**My call:** kept the working title CRM Rethought ([decision 0004](../decisions/0004-name.md)). Naming can wait; research can't.

### Prompt 5 · Tooling
**Prompt:**
> Is a paid Coder workspace worth it to show interviewers how I build? Compare four options on cost and on what an interviewer actually sees:
> - a paid Coder plan,
> - free self hosted Coder,
> - GitHub Codespaces,
> - plain local VS Code.
>
> Keep anything that recreates a past employer's project structure out of it.

**Why:** decide whether the tool itself adds anything.
**What came back:** no paid plan needed (Coder is free and open source); don't recreate past employer project structures; the edge is the proof (repo, prompts, live prototype), not the editor.
**My call:** VS Code and the terminal, with free local Coder only to show a cloud workspace ([decision 0005](../decisions/0005-tooling.md)).

### Prompt 6 · Setup
**Prompt:**
> Set up the project as its own public repo, not a branch of my portfolio: Next.js, TypeScript and Tailwind, deployed on Vercel from `main`. Give me the commands in order and explain each one in a plain line, so I understand what I'm running instead of just pasting it. Include how to check that each step worked.

**Why:** my first time setting up a project from scratch, and I wanted to understand each step.
**What came back:** a separate repo (its own app, its own Vercel project, no shared history with private work), the commands with plain explanations, and a fix when the first push failed because the GitHub address was never saved.
**My call:** created the GitHub repo and connected Vercel myself. Live at [crm-rethought.vercel.app](https://crm-rethought.vercel.app/).
